## 1. AI ⊃ ML ⊃ DL

| 구분 | 의미 |
|---|---|
| AI | 인간의 지적 능력을 컴퓨터로 구현하는 모든 기술 |
| ML | 데이터에서 규칙을 스스로 학습 (데이터 기반 학습 / 패턴 인식 / 자율적 개선) |
| DL | 여러 은닉층의 인공신경망으로 특징까지 스스로 추출/학습 |

- **지도학습**: 정답(Label) 제공 → 예측/분류 (회귀, 분류)
- **비지도학습**: 정답 없음 → 숨겨진 패턴 발견 (차원축소, 군집화, 연관 규칙)
- **회귀** = 수치 예측(집값 5억), **분류** = 범주 예측(스팸/정상)
- **전통 ML vs DL**: 전통 ML은 사람이 특징을 설계(Feature Engineering), DL은 모델이 특징을 학습(Representation Learning)이라 비정형 데이터(이미지/음성/텍스트)에 강하다.

## 2. ML의 "학습"이란?

> **정답과 예측값의 차이(오차 = y − ŷ)가 최소가 되도록 weight(가중치)를 반복 조정하는 과정**

- 신경망 구조: Input layer → Hidden layer → Output layer
- 예제(아파트 가격 예측): 입력 평수(x1), 연식(x2) → 은닉 h1, h2 → 출력 가격(ŷ)
  - `h1 = w11·x1 + w12·x2`, `h2 = w21·x1 + w22·x2`, `ŷ = w31·h1 + w41·h2`

## 3. LLM

- **정의**: 대규모 데이터로 학습한 딥러닝 기반 언어 모델. **문맥을 보고 다음 단어를 예측**한다. 대부분 Transformer 기반(GPT, BERT)
- 관계: NLP ⊃ LM(다음 단어 예측) ⊃ LLM(수십억 파라미터, GPT-3는 175B)
- LM 진화: Statistical(1990s) → Neural(2013) → Pre-trained(2018) → LLM(2020s)
- LLaMA: 2023.2 연구용 → 2023.7 LLaMA 2(상업용 허용, 오픈 LLM 생태계 기폭제) → 2024.4 LLaMA 3
- LLM은 **데이터베이스가 아니라 추론 엔진**. 추론 = 주어진 정보와 문맥으로 새 결과를 도출하는 것
- **Scaling Law**: 모델 크기, 데이터, 연산량이 커질수록 성능이 규칙적으로 향상
- **Emergent Ability**: 규모가 임계점을 넘으면 예기치 않은 새 능력이 비선형적으로 등장

## 4. 생성형 AI

- 학습한 패턴으로 프롬프트에 따라 텍스트, 이미지, 음악, 영상, 코드를 새로 생성
- 발전: 2017 Transformer → 2022 ChatGPT → 2023 GPT-4 멀티모달 → 2024~25 AI Agent
- **텍스트 원리**: 다음 단어별 확률을 매겨 고른다 ("나는 오늘 학교에 가서" → 공부했다 45% 등)
- **이미지 원리**: 텍스트와 이미지를 **같은 벡터 공간에 정렬(align)**. 같은 의미 = 가까운 좌표라서 이미지도 확률 예측으로 생성
- 트렌드 키워드: 멀티모달, 에이전트, 온디바이스 AI, RAG/기업형 AI, AI 거버넌스. **데이터는 AI의 연료**

## 5. AI 이슈와 한계

**환각(Hallucination)**: 사실과 다르거나 학습 데이터에 없는 내용을 만들어내는 현상

- 원인: LLM은 **손실 정보 압축기**. 패턴/확률을 파라미터에 압축 → 세부 사실 손실 → 빈 곳을 "가장 그럴듯한 답"으로 채움
- 예: 존재하지 않는 "고종의 맥북 도난 사건"을 그럴듯하게 설명

| 이슈 | 핵심 |
|---|---|
| 편향 | 학습 데이터의 편향이 결과에 반영 (이미지 생성 AI가 인종차별적 이미지 생성) |
| 안전성 | Violation Percentage = 민감한 요청에 부적절하게 응답하는 비율. 모델마다 차이 큼 |
| 윤리 | 프라이버시 보호 / 책임감 있는 사용 / 정확한 정보 제공 / 모델 한계 인정 |
| 저작권 | AI 생성 작품의 대회 수상, AI 생성 의혹 사례 |
| 비용 | AI 서버 전력 소비 급증 전망. 같은 성능의 LLM 비용은 매년 약 10배씩 하락 |
| 보안 | 업무 중 민감 정보 입력 → 기밀 유출 위험 (생산성 vs 보안 딜레마) |
| 최신성 | 학습 시점 이후 정보는 모르거나 부정확 |

- Token = LLM이 처리하는 최소 단위 (1M 토큰 ≈ 영어 75만 단어)

## 6. 프롬프트 엔지니어링

- **Prompt Engineering**: 원하는 결과를 얻도록 프롬프트를 설계/최적화하는 사용자의 기술
- 모델의 능력: Instruction Tuning(지시 이해), In-Context Learning(프롬프트로 패턴 추론)

**프롬프트 5요소**

| 구분 | 요소 | 의미 |
|---|---|---|
| 입력 | 역할 | AI의 입장 설정 (예: 식품 마케팅 전문가) |
| 입력 | 맥락 | 충분한 배경 정보 |
| 입력 | 명령 | 구체적 지시사항 |
| 출력 | 형식 | 결과물의 구조 (표, 단락, JSON 등) |
| 출력 | 어조 | 말투, 분위기, 스타일 |

- RIO = Role / Instruction / Output (5요소의 간단 버전)
- **더 나은 결과를 위한 6가지 전략**: 세부정보 포함, 페르소나 요청, 구분 기호 사용, 작업 단계 지정, 예시 제공, 출력 길이 지정
- 핵심: 모델이 추측할 여지를 줄일수록 원하는 결과가 나온다
  - 나쁜 예: "회의록 요약해줘"
  - 좋은 예: "한 문단으로 요약 → 화자별 핵심을 마크다운 목록으로 → 다음 액션 아이템 정리"
- 프롬프트용 마크다운: `#` 제목, `1.`/`-` 상하 관계, `---` 구분선, `[]` 참고자료, `*`/`**` 강조

## 오늘의 핵심 정리

1. LLM은 **다음 단어를 확률로 예측**하는 모델이고, 이미지 생성도 같은 확률 예측 원리다.
2. ML 학습 = **오차를 줄이도록 weight를 조정**하는 것.
3. LLM은 손실 압축기라서 **환각이 생긴다**. 결과는 반드시 검증한다.
4. 좋은 프롬프트 = **역할 · 맥락 · 명령 · 형식 · 어조**.
